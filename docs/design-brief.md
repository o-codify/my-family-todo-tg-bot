# Family Todo — дизайн-бриф для Claude Design

Telegram Mini App для семейного списка задач. Этот документ — ТЗ для генерации дизайна экранов. Описывает что рисовать, зачем, какие состояния учесть.

> **Статус:** все экраны из этого брифа реализованы (см. `docs/tech-plan.md`, раздел 10). Несколько отступлений от исходной спецификации зафиксированы в самом разделе ниже:
>
> - **Bottom nav:** в исходном брифе сказано «не делать собственный bottom nav». Мы его всё-таки сделали — 4 вкладки (Calendar/Queues/Rewards/Profile), потому что Telegram BackButton+MainButton не покрывали навигацию для 4 равноправных корневых разделов. Это сознательное расхождение.
> - **Реализованные референсы выбора:** для каждой группы экранов мы выбрали один вариант из дизайна (см. `docs/design/family-todo/project/app.jsx`). Они задокументированы в коде комментарием `Port of …V1`.
> - **Фото-пруф** — фото живут в Telegram (см. tech-plan §9), не в S3. Для дизайна это означает, что в чате с ботом после загрузки появляется отдельное сообщение с кнопками `Открыть задачу` / `Удалить фото`.
> - **Long-press FAB-меню** (см. §4.2) — не реализован; FAB просто открывает CreateTaskSheet. Доступ к шаблонам/каталогу — через профильные ссылки.

## 1. Контекст продукта

**Что это:** Telegram Mini App + бот, в котором семья ведёт общий список задач. Бот шлёт напоминания и уведомления, Mini App — основной интерфейс.

**Кто пользователи:**
- Взрослые члены семьи (создают задачи, ведут календарь, видят статистику, назначают награды).
- Дети (выполняют, отмечают, видят свои задачи, очки и доступные награды). Ограниченные права через роль.
- Размер семьи: до 99 человек.

**Роли:**
- **Owner** — создатель семьи, не редактируется. Полный доступ + управление ролями.
- **Adult** — стандартная взрослая роль (создавать, редактировать, удалять любые задачи, назначать награды).
- **Child** — ограниченная роль (выполнять, отмечать, видеть свои задачи; нельзя удалять чужие). Список прав каждой роли редактируется владельцем.

**Главный сценарий:** утром человек открывает бота → видит дайджест → жмёт «Открыть» → попадает в календарь на сегодня → выполняет задачи, отмечает их, видит, кто что сделал.

**Главная ценность:** видно, что и кому делать, нет несправедливости, ничего не забывается.

## 2. Принципы дизайна

1. **Telegram-native.** Использовать переменные темы TG (`themeParams`): `bg_color`, `text_color`, `hint_color`, `button_color`, `button_text_color`, `secondary_bg_color`. Никаких собственных «брендовых» оттенков фона/текста — только акценты.
2. **Mobile-first.** Базовый размер — iPhone 13 (390×844), но layout должен тянуться от 320px до 600px ширины.
3. **Тач-цели ≥ 44px.** Mini App открывается в TG в полу-экране и фуллскрине — учитывать обе высоты.
4. **Цвета участников** — у каждого члена семьи свой цвет (палитра ниже). Используется для аватара, точек на календаре, бейджей ответственности.
5. **Светлая и тёмная темы** — оба макета обязательны.
6. **Минимум модалок.** Боттом-шиты для большинства действий (создание задачи, детали).
7. **Никакого нативного контрола, который TG не отрисует** — забыть про `<select>`, кастомные пикеры.

## 3. Дизайн-токены

### Палитра участников

Базовые 8 цветов (фиксированы), остальные — генерация по HSL с шагом по hue. Пользователь выбирает свой при онбординге, может сменить.

| # | Имя цвета | Hex (light) |
|---|---|---|
| 1 | Coral | `#FF6B6B` |
| 2 | Sky | `#4ECDC4` |
| 3 | Sun | `#FFD93D` |
| 4 | Mint | `#6BCB77` |
| 5 | Lavender | `#A66CFF` |
| 6 | Peach | `#FF9F68` |
| 7 | Ocean | `#3D8BFD` |
| 8 | Rose | `#E83E8C` |

Цвета должны иметь читаемый контраст текста (белый или тёмный) — указать в дизайн-системе.

> **Important:** В сетке календаря и avatar-stack’ах при 8+ участниках не пытаемся показать всех — показываем топ-N по активности дня + «+N».

### Семантика

- `success` — выполнено
- `warning` — близкий дедлайн
- `danger` — просрочено
- `muted` — бездатные / отложенные

### Типографика

- Системный TG-стек: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, ...`.
- Размеры: 13 / 15 / 17 (body) / 20 / 24 / 28 (titles).
- Жирность: 400 / 500 / 600.

### Отступы и радиусы

- Spacing: 4, 8, 12, 16, 20, 24.
- Radius: 8 (мелкое), 12 (карточки), 16 (шиты), 999 (пилюли/аватары).
- Тени — минимально, только на FAB и плавающих шитах.

## 4. Экраны (что нужно нарисовать)

Для каждого экрана нужны: **light + dark**, и где помечено — **состояния** (empty, loading, error).

### 4.1. Онбординг

Три шага:
1. **Приветствие** — короткое объяснение, кнопка «Создать семью» / «Войти по коду».
2. **Создать семью** — поле «название», аватар (опц.), выбор цвета для себя.
3. **Войти по коду** — поле инвайт-кода, превью семьи перед входом.

После онбординга — переход на главный.

### 4.2. Главный — Календарь (месяц) ⭐ ключевой

**Сверху:** название месяца + стрелки навигации, аватары участников (фильтр), справа — счётчик очков пользователя (тап → экран геймификации).

**Сетка месяца:**
- Дни недели сверху.
- В клетке дня: число + до 3 цветных точек (по числу задач, цвет = ответственный). Если задач больше 3 — последняя точка с цифрой «+N».
- Сегодняшний день выделен (рамка или фон).
- День с просрочкой — красная точка/индикатор.
- Выбранный день — заливка `button_color` с прозрачностью.
- На день, в который выполнена бездатная задача (только текущий месяц), — отдельный «галочка»-маркер в углу клетки.

**Под календарём — секции:**
1. **Задачи выбранного дня** — карточки задач.
2. **Свободные задачи** — раскрывающийся блок «Когда-нибудь» с бездатными задачами (queued и floating).
3. **Список покупок / каталог** (опц. свёрнутая секция) — быстрый доступ к каталогу семьи.

**FAB** в правом-нижнем углу — «+ задача» (long-press → меню: «+ из шаблона», «+ из каталога»).

Состояния: пустой день (нет задач), пустая семья (нет задач вообще), загрузка скелетоном.

### 4.3. Главный — Календарь (неделя)

Альтернативный режим того же экрана:
- Горизонтальная полоса с 7 днями, под каждым — миниатюрный список задач.
- Переключатель «Месяц / Неделя» в шапке.

### 4.4. День (детальный)

Открывается тапом на день календаря, либо через дайджест бота.

- Заголовок: дата прописью.
- Фильтр «Все / Мои / По участникам».
- Список карточек задач, сгруппированных:
  - Просрочено (если есть).
  - На сегодня.
  - Выполнено (свернуть/развернуть).
- Карточка задачи: чекбокс слева, цветная полоса ответственного, заголовок, бейджи (повтор, очередь), кнопка «···».

### 4.5. Карточка задачи (боттом-шит)

Открывается тапом на задачу.
- Заголовок (редактируется тапом).
- Описание.
- Ответственный (chip с аватаром, тап → смена).
- Тип задачи + расписание (если повторяется).
- **Дедлайн** (если задан) — отдельной строкой «До: пт, 24 мая». Дедлайн ≠ дата планирования; задача может быть бездатной, но с дедлайном.
- Очередь (если `queued`) — список «Сейчас: Маша → Дальше: Вася → Я» + индикатор баланса (сколько раз каждый делал).
- **Подзадачи** (чек-лист) — список с прогресс-баром «3/5», тап на каждую — отметка готовности.
- **Награда** — бейдж «+10 очков», если назначена.
- **Фото-пруф** — если требуется: кнопка «Прикрепить фото» (камера/галерея). Если уже выполнена с фото — превью.
- Действия: «Выполнил», «Передать», «Перенести», «Удалить» (последнее — danger, видимо в зависимости от роли).
- История последних выполнений (с миниатюрами фото, если есть).

### 4.6. Создать/редактировать задачу (боттом-шит)

- Поле «Что сделать» — с autocomplete-подсказками из каталога семьи.
  - Под полем — переключатель **«Добавить в каталог»** (если введённое название отсутствует в каталоге).
- Тип задачи — сегментированный контрол: `Разовая | Повтор | Без даты | По очереди`.
- В зависимости от типа — динамические поля:
  - **Разовая:** выбор даты + опц. время.
  - **Повтор:** ежедневно / по дням недели (чипы Пн–Вс) / интервал. Опц. **«кулдаун»** — задача может пересоздаться через N дней после выполнения (для «купить сахар»).
  - **Без даты:** опц. чекбокс «исчезает после выполнения» (single-shot) vs «остаётся, можно делать снова».
  - **По очереди:** список участников. Порядок не важен — балансировка автоматом (равное число выполнений). Можно вручную задать «следующий», но это разовое.
- Ответственный (для всех кроме «По очереди»).
- **Дедлайн** — отдельное поле «Сделать до …», опционально, независимо от даты планирования.
- **Подзадачи** — добавлять чек-листом, drag-reorder.
- **Награда (очки)** — числовое поле, дефолт зависит от типа.
- **Требовать фото-пруф** — тоггл.
- Напоминание — опционально (за сколько до).
- Кнопка «Создать» внизу, sticky. Если редактирование — «Сохранить» + «Удалить» (danger).

### 4.7. Очередь (отдельный лист)

Все задачи типа `queued`:
- Карточка очереди: название + текущий ответственный (крупно) + следующий.
- Индикатор баланса — для каждого участника показать количество выполнений в виде маленьких стобиков (видно, кто отстаёт/обгоняет).
- Тап → история передач, кнопка «Я выполнил».
- Кнопка «Я в отъезде / болею» (away-mode toggle) — пока активно, очередь пропускает пользователя.

### 4.8. Профиль семьи

- Название и аватар семьи.
- Список участников с цветами и ролями. Тап на участника → его профиль (см. 4.9).
- Кнопка «Пригласить» → шарит инвайт-ссылку через TG (`Telegram.WebApp.switchInlineQuery`).
- Для владельца — управление ролями (см. 4.11), кнопка «Удалить семью» (danger).
- «Покинуть семью» — для не-владельцев.

### 4.9. Профиль пользователя

- Аватар (из TG), имя.
- Выбор цвета.
- **Часовой пояс** — индивидуально, дефолт по TG locale.
- **Away-mode** — глобальный тоггл «Я в отъезде до …» (опц. дата возврата). Задачи из очередей пропускают.
- Настройки уведомлений: тихие часы (от–до), утренний дайджест (вкл/время), напоминания за N минут.
- Язык интерфейса.

### 4.10. Статистика (MVP)

- Сегментированный контрол: «Неделя | Месяц | Всё время».
- Графики «кто сколько сделал» — bar chart по участникам.
- Карточка стриков: «У тебя 7 дней подряд», «У Маши 12 дней» (текущий и рекорд).
- Топ задач по частоте.
- «Несправедливость» — индикатор разрыва между самым активным и пассивным.
- Тап на участника — детализация: разбивка по типам задач, история.

### 4.11. Роли и права (для владельца)

Отдельный экран, доступ из профиля семьи.
- Список ролей: Owner (read-only), Adult, Child + возможность создать кастомную.
- Тап на роль → список прав чек-листом:
  - Создавать задачи
  - Редактировать свои задачи
  - Редактировать чужие задачи
  - Удалять свои задачи
  - Удалять чужие задачи
  - Управлять каталогом
  - Создавать шаблоны
  - Назначать награды
  - Получать награды (отметка «получил приз»)
  - Видеть статистику других
  - Приглашать новых участников
- Назначение ролей участникам — через профиль семьи, тап «···» рядом с участником.

### 4.12. Шаблоны задач

Доступно из FAB long-press или из меню задач.
- Список шаблонов семьи: иконка + название + тип задачи.
- Создание шаблона: тот же шит, что для задачи, но с тоггл «сохранить как шаблон».
- Применение: тап → открывается шит создания задачи с предзаполненными полями.
- Системные шаблоны (стартовый набор): «Вынести мусор», «Помыть посуду», «Купить хлеб», «Полить цветы» — можно скрыть.

### 4.13. Каталог (товары / вещи)

Отдельный экран — общая база семьи.
- Поиск + категории (Продукты / Бытовое / Прочее — гибко).
- Карточка: название, последняя цена (опц.), иконка/эмодзи, частота покупки.
- Действие: «Добавить задачу» (создаёт задачу с этим товаром) или «Отметить как куплено» (если уже была активная задача).
- Создание элемента каталога — отдельный шит или inline.
- Каталог растёт автоматически от тоггла в форме создания задачи.

### 4.14. Геймификация — очки, стрики, лидерборд

- Главный блок: твои очки (крупно), стрик, ранг в семье.
- **Лидерборд** — все участники с очками, цветами и аватарами. Опц. фильтр по периоду.
- **История очков** — что за что начислено.
- **Награды (магазин)** — каталог призов, назначенных взрослыми. Карточка приза: название, изображение/эмодзи, стоимость в очках, кнопка «Получить» (если хватает очков).
  - Назначение призов — отдельный шит, доступен с правом «Назначать награды»: название, эмодзи, стоимость, описание, кто может получить (опц.).
  - История полученных призов.
- Ребёнок видит экран как «магазин», взрослый — с дополнительной вкладкой «Управление призами».

## 7. Состояния и edge-cases

- **Пустая семья** (нет ни одной задачи) — иллюстрация + «Создать первую задачу» + «Выбрать из шаблонов».
- **Один участник** в семье (ещё никого не пригласил) — баннер «Пригласить близких».
- **Просроченные задачи** — отдельный коллапс наверху списка дня.
- **Задача без ответственного** — серый плейсхолдер вместо цвета.
- **Очередь, в которой только один человек** — показывать как обычную задачу.
- **Все в очереди в away-mode** — задача помечена «Некому делать», предлагается передать вручную.
- **Длинные имена / заголовки** — обрезка с `…`, до 2 строк в карточке.
- **Оффлайн / ошибка сети** — баннер сверху.
- **Ребёнок пытается удалить задачу без прав** — кнопка скрыта или отображается с пометкой «нет прав».
- **Очков на награду не хватает** — кнопка disabled + подсказка «не хватает N очков».
- **Бездатная задача выполнена в прошлом месяце** — на текущем месяце не отображается (в истории остаётся).
- **Каталог пустой** — empty state «Каталог растёт сам — добавь товар при создании задачи».
- **Фото-пруф требуется, но не приложено** — кнопка «Выполнил» disabled с подсказкой.

---

## 8. Что НЕ нужно делать

- Не рисовать отдельный экран входа/регистрации — авторизация через Telegram автоматически.
- Не делать боковое меню (drawer) — TG это плохо терпит.
- Не использовать swipe-to-delete как единственный способ удаления — есть «···».
- Не делать собственный bottom nav — навигация через TG `BackButton` и `MainButton`.

## 9. Формат сдачи

Что хочется получить от Claude Design:

1. **Файл Figma-like** со всеми экранами в light + dark.
2. **Страница «Дизайн-система»** — токены, компоненты, состояния.
3. **Превью основных флоу** — последовательность экранов:
   - Онбординг (создание семьи).
   - Создание повторяющейся задачи с подзадачами и фото-пруфом.
   - Создание задачи из каталога с автодополнением.
   - Передача очереди + индикатор баланса.
   - Выполнение бездатной задачи и её отображение на календаре.
   - Ребёнок зарабатывает очки → забирает приз в магазине.
   - Владелец редактирует права роли «Child».
4. **Описание интерактивов** — что куда ведёт, какие переходы.
